  1 | # LegacyLink AI
  2 | 
  3 | **IBM Bob-assisted legacy SQL schema modernization into clean Python ORM codebases**
  4 | 
  5 | Built for the IBM Bob Hackathon by lablab.ai.
  6 | 
  7 | ## Overview
  8 | 
  9 | LegacyLink AI is a lightweight modernization tool that converts messy legacy SQL schema files into clean, modern Python ORM project scaffolds. It helps developers understand old database systems faster, reduces repetitive ORM coding, and improves documentation and test readiness.
 10 | 
 11 | ## Features
 12 | 
 13 | - **SQL File Upload**: Upload `.sql` or `.txt` files containing `CREATE TABLE` statements.
 14 | - **Schema Parsing**: Automatically extract tables, columns, and constraints.
 15 | - **Name Cleaning**: Convert cryptic legacy names to clean, modern conventions.
 16 | - **ORM Generation**: Generate SQLAlchemy 2.0 models with proper type hints.
 17 | - **Test Generation**: Create starter pytest test files.
 18 | - **Modernization Report**: Generate a detailed explanation of all transformations.
 19 | - **ZIP Download**: Download the complete project scaffold.
 20 | - **AI Assistant**: Use an optional IBM watsonx.ai-powered assistant to answer questions about the schema.
 21 | - **PostgreSQL Audit Logging**: Optionally log AI Assistant Q&A interactions for traceability.
 22 | - **MCP Audit Access**: Optionally expose PostgreSQL audit logs to IBM Bob through a local Model Context Protocol server.
 23 |

 63 | ## AI Assistant
 64 | 
 65 | LegacyLink AI includes an optional AI Assistant powered by **IBM watsonx.ai**. It can answer questions about parsed schemas, generated SQLAlchemy ORM models, legacy naming transformations, and modernization reports.
 66 | 
 67 | ### Setup
 68 | 
 69 | To enable the AI Assistant, create `.streamlit/secrets.toml` with your IBM watsonx.ai credentials:
 70 | 
 71 | ```toml
 72 | WATSONX_API_KEY = "your-api-key-here"
 73 | WATSONX_PROJECT_ID = "your-project-id-here"
 74 | WATSONX_URL = "https://us-south.ml.cloud.ibm.com"
 75 | WATSONX_MODEL_ID = "ibm/granite-4-h-small"
 76 | ```
 77 | 
 78 | ### Getting IBM watsonx.ai Credentials
 79 | 
 80 | 1. Sign up for [IBM Cloud](https://cloud.ibm.com/).
 81 | 2. Create a watsonx.ai project.
 82 | 3. Generate an API key from your IBM Cloud account.
 83 | 4. Copy your project ID from the watsonx.ai project settings.
 84 | 
 85 | ### Example Questions
 86 | 
 87 | - "Explain this schema to a new developer"
 88 | - "Which columns look like foreign keys?"
 89 | - "What legacy naming patterns were fixed?"
 90 | - "Summarize the modernization report"
 91 | - "What should a developer review first?"
 92 | 
 93 | The AI Assistant uses the **ibm/granite-4-h-small** foundation model by default. This feature is completely optional; the core parser, generator, report, and ZIP download flow works without watsonx.ai credentials.
 94 | 
 95 | ## PostgreSQL Audit Logging and MCP
 96 | 
 97 | LegacyLink AI includes optional PostgreSQL audit logging for AI Assistant Q&A interactions. When enabled, the app records each AI Assistant question, answer, source context, SQL filename, table count, model ID, status, and timestamp in a PostgreSQL table named `ai_assistant_logs`.
 98 | 
 99 | This audit log can also be exposed to IBM Bob through the **Model Context Protocol (MCP)**. MCP is part of the development and review workflow: it lets IBM Bob inspect local audit records while helping debug, explain, or review the project. MCP is not required for the Streamlit app, schema upload, code generation, ZIP download, or watsonx.ai runtime assistant.
100 | 
101 | ### Audit Logging Setup
102 | 
103 | 1. Create a PostgreSQL database, for example `legacylink_audit`.
104 | 2. Create the `ai_assistant_logs` table using the SQL in [docs/POSTGRES_AUDIT_LOGGING.md](docs/POSTGRES_AUDIT_LOGGING.md).
105 | 3. Add PostgreSQL settings to `.streamlit/secrets.toml`:
106 | 
107 | ```toml
108 | POSTGRES_AUDIT_ENABLED = true
109 | POSTGRES_HOST = "localhost"
110 | POSTGRES_PORT = "5432"
111 | POSTGRES_DB = "legacylink_audit"
112 | POSTGRES_USER = "postgres"
113 | POSTGRES_PASSWORD = "your-secure-password"
114 | ```
115 | 
116 | If `POSTGRES_AUDIT_ENABLED` is missing or set to `false`, the app skips database logging and continues normally.
117 | 
118 | ### IBM Bob MCP Configuration
119 | 
120 | The local Bob MCP configuration lives in `.bob/mcp.json` and uses the PostgreSQL MCP server:
121 | 
122 | ```json
123 | {
124 |   "mcpServers": {
125 |     "legacylink-postgres-audit": {
126 |       "command": "npx",
127 |       "args": [
128 |         "-y",
129 |         "@modelcontextprotocol/server-postgres",
130 |         "postgresql://USER:PASSWORD@HOST:PORT/legacylink_audit"
131 |       ],
132 |       "disabled": false
133 |     }
134 |   }
135 | }
136 | ```
137 | 
138 | Replace `USER`, `PASSWORD`, `HOST`, and `PORT` with your local PostgreSQL values. Keep `.bob/mcp.json` out of git because it can contain local credentials.
139 | 
140 | With MCP enabled, IBM Bob can inspect records such as recent AI Assistant questions, failed interactions, model IDs used, and context types used during schema modernization reviews.
141 | 
142 | For the full table schema, example SQL queries, and troubleshooting details, see [docs/POSTGRES_AUDIT_LOGGING.md](docs/POSTGRES_AUDIT_LOGGING.md).
